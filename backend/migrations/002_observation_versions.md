# 002 观测版本化与修订报表导入

供应方补发修订日报后，台账需要按报表版本保留每个 (序列, 日期) 的最新观测，并支持带逐行预览的批量导入。

## 变更（全部为增量变更，不删除既有约束）

1. `observations` 增加列：
   - `report_version INT NOT NULL DEFAULT 0`：供应方报表版本，未携带版本的历史观测为 0，越大越新。
   - `batch_id INT NULL`，外键 `import_batches.id`：最近一次写入该观测的导入批次。
2. 保留既有唯一键 `uq_series_day(series_id, day)`：它从「拒收重复日期」的业务限制转为「每个日期物理一行」的硬不变量。版本高低、同版异值等业务规则由导入服务判定，任何并发同日写入仍会被数据库拒绝并进入调和流程，因此不会产生重复日观测。
3. 新增索引 `ix_obs_series_day_ver(series_id, day, report_version)`：预测读取与按版本比对的查询路径。
4. 新表 `import_batches`：导入批次台账，`idem_key` 唯一保证重复/并发导入同批不新增观测；保存输入总数与各类处置计数、逐行处置结果，便于核对与重放。

## 升级方式

应用启动时 `src.config.migrations.ensure_schema` 幂等执行（检查 information_schema 后再变更），可重复运行；全新库由 `Base.metadata.create_all` 直接建立新结构，不触发 ALTER。升级不删除/重建任何既有唯一约束，历史数据零搬迁，既有观测的 `report_version` 取默认值 0。

## 语义

- 每个 (series_id, day) 只保留 `report_version` 最高的一条；高版本更正覆盖低版本数值，低版本重放不回退数值。
- 同版异值（文件内或与库内同版本冲突）整组隔离为冲突行，不入库。
- 无版本（v0）观测可被首个携带版本的同日期观测升级；升级后该观测继续可用于预测。
- 并发导入：事务按日期排序加行锁；未锁住的同日插入由 `uq_series_day` 拒绝，失败事务回滚后重新规划，将竞争行降级为跳过/冲突隔离，好行照常入库。
- 预测在计算时实时读取观测表，更正后的观测自动进入后续预测；已完成的历史运行结果不回改，保持可追溯。
